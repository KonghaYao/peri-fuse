# 会话文本定位：性能优先设计

日期：2026-09-14。状态：设计草案，尚未实现。

## 目标与首版范围

输入记得的一段对话，在搜索弹窗中点击命中条目查看前后上下文，判断是否为目标会话，
再选择进入相关 trace/observation；点击命中条目本身不跳转页面。
已确认搜索范围为 user 与 assistant（AI）消息的正文；界面只提供正文和时间范围两个搜索条件。
工具消息、system/developer 消息、名称、标签和 ID 统一搜索不属于本功能范围。

首版采用 SQLite FTS5 + 独立搜索投影，存放在现有 telemetry.db，不引入外部服务。
公开 sessions 列表继续遵守原有 SDK 分页契约；新增搜索入口只承担快速定位。

当前实现依据：

- [Sessions 列表](../packages/server/src/routes/sessions.ts)从 traces 派生会话，聚合 metrics、users、tags 后分页，另做精确计数。
- [Sessions 页面](../packages/web/src/features/sessions/sessions-page.tsx)已有用户、环境和时间过滤，无正文搜索。
- [Telemetry adapter](../packages/shared/src/server/adapters/sqlite-telemetry-adapter.ts)支持事务批量写入，但通用 insert 使用 INSERT OR REPLACE。
- [SQLite 读取池](../packages/shared/src/server/adapters/sqlite-read-pool.ts)已有有界队列、取消、超时和结果字节限制。

搜索不会复用会话列表的聚合 SQL，也不会对原始 input/output 使用 LIKE '%关键词%'。
已有的响应缓存只能优化重复查询，不能承担搜索性能保证。

## 用户体验与匹配语义

Sessions 顶部提供“搜索会话”入口，打开搜索弹窗。弹窗顶部为“搜索用户或 AI 消息正文”输入框、
时间选择器和搜索按钮；Enter 或搜索按钮提交。
首版不随输入自动请求；可取消进行中的搜索，旧请求不能覆盖新结果。

默认范围为当前项目、最近 1 小时。建议快捷选项：最近 1 小时、6 小时、24 小时、7 天，以及自定义起止时间。
自定义区间必须同时提供起止时间；首版不提供无界的“全部时间”。正文要求 3–128 个 Unicode 字符。
时间选择在修改关键词时保留；初次打开默认 1 小时，重新搜索时重新计算相对时间范围。

这里的时间指**承载命中消息的遥测记录时间**，不是会话创建时间或索引写入时间：
observation 使用 start_time，trace-only 消息使用 trace.timestamp。
模型请求携带的历史 user/assistant 消息仍可命中该次请求；不能把请求时间称为历史消息的原始发送时间。
结果展示“记录时间”。同一文本在时间窗口内有有效来源时才返回，不能用最后索引时间代替。

相对时间由服务器在请求开始时固定为 `[now - range, now)`，自定义区间同样使用左闭右开边界。
返回实际起止时间，前端按用户时区显示；数据库比较统一使用 UTC，避免客户端时钟偏差。

每次最多返回 20 个会话，每个会话最多两个约 160 字的命中片段，以及：

- 会话 ID、用户标识（有则显示）、命中时间。
- 命中来源：用户消息或 AI 消息，片段保留实际 role。
- traceId / observationId / 来源字段，支持详情页面打开对应位置。

点击结果仅加载该命中对应的上下文预览；选择“打开完整会话”后再导航并定位目标 trace/observation。
完整页面也先加载会话壳和目标详情，不自动加载整个会话 IO。
首版不提供页码、精确总数和“全局最新会话”排序；结果按相关命中组织。
未展示的候选不被解释成“不存在”，达到预算时提示补充关键词或缩小时间范围。

索引和查询使用同一版本的 Unicode 规范化与大小写处理。首版是规范化后的连续片段匹配，
不是语义搜索、错字纠正或任意 FTS 表达式。引号、星号等按文本处理，由后端编译 MATCH 参数。

SQLite trigram 对少于 3 个 Unicode 字符的全文查询不返回命中；这一限制已在本地 SQLite 3.49.2
用“退款／退款失／退款失败／timeout”验证。生产启动还需探测功能支持。
两字中文若是刚需，应单独设计 bigram 倒排索引并测存储、热门词与写入成本，不能用扫描兜底。
参见 [SQLite trigram 文档](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)。

## 搜索弹窗与上下文预览

桌面端采用左右两栏的大弹窗，建议宽度不超过 1,200px、高度约 80vh；左侧约 35% 展示结果，
右侧约 65% 展示上下文，两栏独立滚动。窄屏采用“结果 → 上下文”的单栏切换，并提供返回结果按钮。

```text
┌ 搜索会话 ─────────────────────────────────────────────── 关闭 ┐
│ [搜索 user / AI 正文……             ] [最近 1 小时 ▾] [搜索]  │
├────────────────────┬────────────────────────────────────────┤
│ 会话 A · 10:42     │ 会话 A · 命中记录 10:42                  │
│ 用户：退款失败……   │                         [打开完整会话]  │
│                    │              加载更早消息                │
│ 会话 B · 10:36     │ 用户：我想退回昨天的订单                  │
│ AI：退款失败时……   │ AI：请问你遇到了什么提示？                │
│                    │ 用户：页面提示【退款失败】 ← 命中         │
│                    │ AI：请检查订单目前的状态                  │
│                    │              加载后续消息                │
└────────────────────┴────────────────────────────────────────┘
```

交互规则：

- 搜索完成后展示结果，右侧提示“选择一条结果查看上下文”；首版不自动请求第一个结果的上下文。
- 左侧以会话分组，每个命中片段是独立可选条目。同一会话多个命中拥有各自的定位锚点。
- 点击或键盘选中后，右侧显示局部 loading，再展示命中消息前后各 2 条 user/AI 消息，合计最多 5 条。
- 命中消息自动滚动到可见位置，正文中高亮实际命中区段；上下文按消息原有顺序展示。
- 预览顶部保留会话 ID、记录时间和“打开完整会话”；长消息明确显示“正文已折叠”，可继续展开。
- 向前／后加载均由用户触发，每次最多 5 条。切换命中不关闭弹窗，不丢失左侧搜索词、时间范围和滚动位置。
- 更换搜索条件并重新提交时清除旧选中项，取消正在进行的上下文请求。
- Esc 关闭，关闭后焦点回到入口；键盘可在结果间移动并打开预览，焦点限制在弹窗内。

### 上下文含义与真实性

上下文指**命中来源记录中可验证的消息序列**，仍只展示 user/assistant 正文。
默认由该次请求的 messages 顺序和可明确关联的模型回答组成，并标注“该次请求中的对话上下文”。
工具和其他角色不展开，预览固定说明“仅显示用户和 AI 消息”，避免被误认为完整执行过程。

不能把同一 session 的所有 observation 按时间简单串起来：分支、并行请求和重复历史会产生错误对话。
只有单条 trace 文本、没有结构化消息顺序时，仅显示可确认的输入／回答，提示“前后文未记录”。
到达当前来源序列边界时提示“当前记录上下文已结束”；完整会话可通过显式跳转查看。
未来跨请求拼接须有可靠 message ID／父子关系后再设计，不按文本相似度猜测上下文。

时间筛选只决定哪些命中条目进入结果；预览可以包含该命中的更早历史消息，不再用搜索时间窗裁剪邻居。
邻居没有独立发送时间时不伪造时间，顶部只显示来源记录时间。

### 上下文读取与性能

复用后台提取产生的有序消息投影，并保存定位锚点：来源类型、来源 ID、来源版本、消息序号、块号。
原始显示文本和规范化检索文本分开表达；高亮区段映射到显示文本，不能直接套用规范化后的偏移。
去重只复用文本存储，不能合并消息 occurrence 或改变同一来源内的消息顺序。

上下文通过项目、来源、版本和消息序号进行范围读取，不能在点击时查询完整 session，
也不能先读出多 MB 原始 input/output JSON 再取其中五条。超长消息按块定位到命中附近，
单条初始显示建议不超过 2 KiB，总响应不超过 32 KiB；命中在消息尾部时仍应显示命中附近正文。

- 弹窗最多一个在途上下文请求；快速切换条目时取消旧请求，响应必须与当前 occurrence 和版本一致。
- 同一弹窗会话内可缓存少量预览，建议上限 10 个、总计 320 KiB，缓存键包含项目、来源版本和命中位置。
- 关闭弹窗、切换项目或退出登录时清理预览缓存，不做所有搜索结果的预取。
- 删除或更新后，预览接口必须重新验证来源；返回“记录已更新／不可用”，不能偷偷跳到另一个相同文本来源。
- 局部读取失败只影响右侧，保留结果列表并提供重试。索引正文尚未准备好时显示状态，不回退为整会话拉取。

## 搜索数据模型

正文按角色白名单提取，只索引明确识别为 user 或 assistant 的可读文本。
识别各支持协议的 message/content 文本结构，不能遍历 JSON 后把所有字符串都拼入正文。
assistant 消息同时包含文本与 tool_calls 时，只提取正文文本；排除工具名、参数和工具返回值。
跳过 system/developer/tool/function 消息、thinking/reasoning 块、图片、音频、base64 及结构化二进制。
不会提供开启工具文本搜索的选项。

对没有 role 的原始字符串，只有来源协议能明确证明其为用户消息或模型最终文本时才映射角色；
不能把所有 input 当 user、所有 output 当 assistant，尤其不能收录工具 span 的 output。
未知角色或 JSON 结构记录未覆盖状态，避免把“没提取到”误报成“没有匹配”。

建议使用以下投影；字段为设计示意，最终 DDL 在实现阶段确定：

| 表 | 用途及关键字段 |
| --- | --- |
| search_texts | INTEGER 主键；project_id、content_hash、chunk_no、display_text、normalized_text、索引版本；支持正文块按需读取 |
| search_occurrences | 文本块到消息来源的关系；occurrence_id、project_id、text_id、source_kind、source_id、trace_id、role、field、message_order、chunk_no、source_version、event_time |
| search_fts | FTS5 trigram：项目 scope 和正文；rowid 对应 search_texts 主键 |
| search_dirty | 持久化待处理来源；project_id、source_kind、source_id、revision、重试状态 |
| search_index_state | 回填进度、覆盖范围、积压、索引版本和最近错误 |

在项目内按提取后的显示文本 hash 和提取版本去重，完全相同历史消息只索引一次，通过 occurrences 保留来源。
不能仅用规范化文本 hash 合并原文不同的消息，否则预览可能展示另一个来源的大小写、字符或排版。
不能删除其他来源仍引用的文本；垃圾回收仅移除无有效引用的文本及对应 FTS 条目。
去重不能跨项目；命中必须返回仍然有效且在本项目内的 occurrence。
相同正文可分别由 user 和 assistant 引用；role 和记录时间保留在 occurrence 上，不因文本去重而丢失。
一个被排除的工具消息即使与有效用户消息正文相同，也不能成为该文本的可搜索来源。

长消息分块，建议每块约 4 KiB，按 Unicode 字符边界切分，重叠至少 127 个字符，
以覆盖最长查询的跨块匹配。单块额外重叠的字节成本计入预算。
全文提取和索引都在后台分批执行；不可只截取头部却宣称整条消息可搜索。

FTS 使用 search_texts 的 external-content 投影，避免正文再复制一份。
正文表、FTS 条目及引用变更在短事务内维护，不把 FTS 直接挂到巨大的 observations 原表。
external-content 的一致性需要应用保证，更新、删除和旧数据回填均须测试，
参见 [SQLite external-content 文档](https://www.sqlite.org/fts5.html#external_content_tables)。

初始索引方向：

- search_texts：UNIQUE(project_id, content_hash, chunk_no, index_version)。
- search_occurrences：(project_id, text_id, event_time DESC, occurrence_id)，用于有界读取来源。
- search_occurrences：(project_id, event_time DESC, occurrence_id, text_id)，用于从指定时间窗口枚举轻量候选。
- search_occurrences：(project_id, source_kind, source_id)，用于来源更新和删除。
- search_occurrences：(project_id, source_kind, source_id, source_version, message_order, chunk_no)，用于预览范围与正文分块读取。
- search_dirty：UNIQUE(project_id, source_kind, source_id)，反复更新合并成一个待处理来源。

## 查询路径与成本上限

对最近 6 小时以内的短窗口，查询可先使用 `(project_id,event_time)` 索引遍历搜索投影，再以规范化正文上的连续字面匹配求交；正文过滤必须发生在候选 LIMIT 之前，因此不能用截断候选的方式伪造完整结果。较宽窗口继续使用 FTS5 MATCH 以避免枚举大量时间候选。两条路径都受相同的 500 ms 可取消预算和候选上限约束，短窗口路径不读取原始 input/output。

1. 从认证取得 projectId，验证正文与时间范围；缺省范围由服务器设为最近 1 小时。
2. 将项目、正文和记录时间的约束纳入同一候选查询；后端把项目 scope 与正文条件编译到 MATCH 中。
3. 对窗口内的有效 user/assistant occurrence 分批取候选，时间过滤必须在结果 LIMIT 之前完成。
4. 批量用项目 + 来源 ID 验证来源当前存在、未删除、版本有效，并通过 traces 获取当前 session_id。
5. 对候选会话去重，最多 20 个结果；只对最终命中提取短片段。

FTS 内 scope 使用后端生成的规范化项目标识，可用固定长度十六进制摘要。
关系表及最终授权检查仍使用真实 project_id；scope 不是鉴权替代品。
不能先对所有项目取 Top K，再过滤项目，否则其他项目会挤掉合法结果。
同样不能先对全部历史取 Top K，再过滤最近 1 小时，否则历史命中会挤掉当前窗口内的会话。

短时间窗口优先评估由 `(project_id, event_time)` 索引驱动，再与 FTS 文本命中求交；
低命中关键词也可评估 FTS 驱动，再按 `(project_id, text_id, event_time)` 查来源。
具体访问顺序以执行计划和基准确认，不能假定 SQLite 自动同时高效使用两个索引。
若采用时间驱动且候选枚举已达到预算，需要返回 limited，不能在有限样本中没找到就宣称整个时间窗口无结果。

建议初始预算：一次最多 200 个匹配文本、1,000 个来源候选，响应不超过 64 KiB。
重复用户消息或 AI 回答即使只索引一份也可能关联大量来源，所以 occurrences 查询本身必须 LIMIT，
不能先展开所有引用再在应用层截断。时间条件在 SQL 中生效不代表 FTS postings 一定被预先裁剪，仍需实测。

**LIMIT 限制返回量，不保证底层检索或排序只处理同样数量的记录。**
热门词、较长的自定义时间窗口、相关性排序仍可能昂贵。因此：

- 搜索使用服务进程管理的独立、有界读取 worker，初始同时执行 1 个、排队 8 个，避免占满现有读取池。
- 建议总预算 500 ms（含排队），按剩余时间下发各步；运行中的 SQL 必须可中断。
- 当前同步 fallback 不能保证在没有产出行时及时打断查询；全文搜索不能依赖该 fallback。
- FTS 超时不退化到原表扫描；已完成的阶段可返回明确标识的不完整结果，否则返回 SEARCH_TIMEOUT。
- 候选不足 20 个也可能已经达到预算，此时不能宣称搜索已穷尽。

首版不承诺对所有命中做精确的全局会话排序。FTS 排名衡量文本块，
不是会话的最终相关性；产品文案不得把候选排序称为完整的会话排名。

## 写入、可见性与删除

通过存储写入事务同时更新 search_dirty，仅记录来源 ID 和 revision，避免同步分词。
worker 从持久化队列读最新内容、提取去重、更新投影，成功后按 revision 条件确认任务。
处理中再次更新来源不能被旧任务清除；进程重启后从队列继续。

来源输入包含多轮历史消息时，先过滤角色与内容类型，再按消息 hash 重用已有文本。流式写入合并处理，
优先在完成事件后索引，未完成记录使用可配置的合并窗口，避免每个 token 重建索引。
索引状态给出新内容延迟与历史覆盖；目标正常负载下 5 秒内可搜索，属于待验证目标。

所有入口都要覆盖：SDK ingestion、OTLP、更新、软删除、物理删除和 retention。
现有 INSERT OR REPLACE 路径不能想当然依赖 DELETE trigger 获得旧行删除通知。
应通过统一写入模块标记来源 dirty；删除与投影失效不能只放在某一条 HTTP 路由中。

FTS 中只保存文本及项目 scope，不固定 session_id；命中后通过当前 trace 解析会话，
可处理 observation 先到、sessionId 后到，以及会话关联发生变化。
来源已删除或版本失效时立即抑制旧命中，再异步清理索引；不返回已经失效的片段。
物理清理必须保留足够的来源标识以清理引用，重试幂等。

后台任务与在线写入共享 SQLite 写锁：初始每批最多 100 个来源且累计读取不超过 2 MiB，
短事务、小批次、写入压力上升时降速。大于预算的单来源需单独流式提取或标记待处理，
不得反复在普通批次中整条 JSON.parse，也不得无提示永久跳过。

首次上线优先处理新增数据，历史回填使用持久化游标，在后台逐批推进。
覆盖未完成时显示“历史内容索引中”，不在服务启动时同步重建全库。
索引版本升级可使用影子投影完成回填后切换；磁盘预算必须包含新旧两份索引的峰值。

## 模块和 HTTP 契约

在 shared 内增加 session-search 模块，对外只暴露搜索和后台生命周期能力。
文本抽取、FTS 语法编译、去重、投影事务、revision、上下文范围读取和查询预算封装在模块内部。
Server 负责认证、参数校验、错误映射；Web 负责交互、片段展示与详情定位。

建议新增 `POST /api/public/session-search`，使用已有项目认证，不修改 SDK sessions 返回格式。

```json
{
  "query": "退款失败",
  "timeRange": { "kind": "relative", "seconds": 3600 },
  "limit": 20
}
```

相对时间 seconds 首版仅接受快捷选项对应的 3600、21600、86400、604800。
省略 timeRange 时服务器使用 3600 秒；自定义格式为
`{ "kind": "absolute", "fromTimestamp": "...", "toTimestamp": "..." }`，要求有效时间且 from < to。
不接受仅省略一端而变为全历史查询；较宽自定义区间仍受相同执行预算约束。

响应为 `{ data, meta }`：data 包含 sessionId，以及各命中的 occurrenceId、sourceVersion、定位锚点和短片段；meta 包含
`returnedSessions`、`limited`、`limitReason`、`indexState`、`coverage`、`resolvedTimeRange`。
`limited` 表示预算导致不完整，不能用 `hasMore: false` 隐藏截断。
不返回虚构的 totalItems；不把查询文本、正文或鉴权内容写入日志。
片段按纯文本与高亮范围返回，前端不直接注入 FTS 生成的 HTML。

空输入时弹窗显示输入提示，不请求普通列表或上下文；短正文返回 QUERY_TOO_SHORT；忙碌返回 SEARCH_BUSY；
超时返回 SEARCH_TIMEOUT；索引未就绪显示明确状态。退出或改词时取消请求。

上下文建议另设 `POST /api/public/session-search/context`：

```json
{
  "occurrenceId": "opaque-hit-id",
  "sourceVersion": 12,
  "before": 2,
  "after": 2
}
```

响应包含 sessionId、来源定位、role 与正文块组成的 messages、命中锚点、可继续读取的前后游标、
逐消息的截断状态及 contextScope。游标绑定项目、来源和版本，接口重新鉴权，不能只相信客户端传入的 ID。
首次 before/after 均限制为 0–2；后续使用方向游标加载最多 5 条消息，消息内部展开另用正文块游标。
邻接消息按 message_order 计数而不是按正文块行数计数，避免一条长消息占掉五条上下文。
版本不匹配返回 CONTEXT_STALE；来源已不存在或不属于项目时返回统一的不可用响应。

## 性能验收与实施顺序

以下是验收目标，尚无百万级基准证明：

| 指标 | 初始目标 |
| --- | --- |
| 指定基准机，百万级索引块，最近 1 小时，低并发，普通关键词 | 暖缓存服务端 P95 < 200 ms |
| 搜索链路预算 | 500 ms，超时／取消行为可靠 |
| 列表响应 | ≤ 20 会话，≤ 64 KiB |
| 单次上下文预览 | 最多 5 条消息，≤ 32 KiB，暖缓存服务端 P95 目标 < 100 ms |
| 预览读取成本 | 按来源位置范围读取；长 session 不应增加单次预览返回量，500 ms 内取消／超时 |
| 正常负载新数据可见性 | P95 < 5 秒 |
| 摄入影响 | 与关闭索引的同负载基线相比，P95 增幅目标 < 10% |
| 存储 | 记录去重率、提取文本字节数、FTS 倍率、回填峰值，再决定启用阈值 |

基准需要固定 CPU、内存、磁盘、查询集和数据分布；同时报告冷缓存、并发、失败率，
不能只统计成功请求而排除热门词超时。按数据字节和会话重复历史长度分层，不只按行数。
分别测量 1 小时、6 小时、24 小时、7 天和较宽自定义窗口；保持最近 1 小时数据量不变、
增加历史数据量，观察默认查询是否随全库体积退化。索引的时间访问方式是本功能的核心验收项。

实施顺序：

1. 按已确认的 user/assistant 正文和默认 1 小时实现协议提取规则；建立中文、英文、跨块和重复消息样本。
2. 实现搜索模块与小型基准，验证 FTS、项目 scope、热门词预算及索引体积。
3. 接入事务 dirty 队列、重启恢复、迟到关联、删除和回填；实现上下文范围读取及两个 HTTP 入口，再加入搜索弹窗。
4. 在实际 telemetry 数据的隔离副本上测查询、写入争用和磁盘放大，达标后逐项目启用。

必测：跨项目同文本、同文本多个会话、同会话重复历史、trace/observation 重复 IO、
晚到 sessionId、更新与回填竞争、源记录删除、retention、进程中断、过长字段、
没有会话的 observation、普通词极高命中、查询取消和队列过载。
另需覆盖：工具 span 输出、assistant 的 tool_calls 参数不命中、混合 content 只提取文本、
同正文不同角色、历史消息在新请求中重复出现、缺省 1 小时、范围切换、UTC／本地时区、
起止边界、窗口内外同文本、索引回填时间不改变记录时间，以及大量窗口外命中不能挤掉窗口内结果。
弹窗额外验收：点击才发起上下文请求、最多一个在途预览、快速切换不串内容、同会话多个命中分别定位、
超长消息尾部命中、跨块高亮、归一化偏移映射、同文不同角色保留位置、窗口外历史可预览、
分支会话不被拼成错误对话、来源更新／删除、缓存隔离、关闭取消、Esc／焦点恢复及窄屏返回结果。

关闭功能后原有会话浏览与摄入必须继续工作；索引可重建，不作为遥测真相来源。
本次只形成设计和功能探测结果，未更改服务或新增全文索引。
